# 단동샘 쇼츠 컷편집 (Codex · 내 컴퓨터 폴더용)

작업 폴더 안의 영상을 **복사·변환·이름 변경 없이 그대로** 읽고, 편집 결과를 `.dsp`(UTF-8 JSON)로 `결과` 폴더에 만든다. 스크립트는 이 스킬의 `scripts/`에 있고, 한글 경로·따옴표 문제를 피하려고 PowerShell 명령 대신 이 스크립트(python)를 쓴다. 이하 `SKILL_DIR`은 이 SKILL.md가 있는 폴더다.

## 지켜야 할 것

1. 원본 영상은 이름도 내용도 바꾸지 않는다. 비율 보정용 복사본·축소본을 만들지 않는다(편집기가 회전·픽셀 비율·화면 비율을 알아서 맞춘다). 새로 만드는 파일은 `원본명_edited.wav`와 `.dsp`뿐이다.
2. 작업 폴더에 임시 파일을 남기지 않는다. 임시 파일은 시스템 임시 폴더(`%TEMP%` 등)에 둔다. 작업 폴더나 `결과` 안의 미디어 파일은 편집기가 원본으로 착각해 잘못 연결할 수 있다.
3. 폴더 안의 `편집설정.json`과 `편집파일_만드는법.txt`(예전 이름: 프로젝트파일_만드는법.txt)가 있으면 먼저 읽고 따른다. 없을 때만 `references/`의 기본값을 쓴다. 사용자가 말한 값이 가장 우선이다.
4. 사용자가 "승인 후 진행"이라고 말하지 않았다면 중간에 멈추지 않는다.
5. 숫자·상품명처럼 불확실한 단어는 자막에 넣지 않는다. 음성 인식이 안 되면 자막을 지어내지 말고 못 만들었다고 알린다.
6. `.dsp`는 UTF-8(BOM 없이)로 저장하고 한글을 `\u` 이스케이프로 바꾸지 않는다(`ensure_ascii=False`).

## 0. 환경 점검 (처음 한 번)

- `python --version`, `ffmpeg -version`, `ffprobe -version`을 확인한다.
- ffmpeg가 없으면(윈도우): `winget install Gyan.FFmpeg` 후 터미널을 새로 연다. 설치는 사용자에게 알리고 진행한다.
- 음성 인식: `python -m pip install faster-whisper`. 첫 실행 때 모델(large-v3-turbo, 약 1.6GB)을 내려받아 시간이 걸린다.

## 1. 폴더 파악

```
python SKILL_DIR/scripts/probe.py "<작업 폴더>"
```

각 파일의 길이, **보이는 크기**(회전·픽셀 비율 반영), 소리 유무가 나온다. 영상용 소스와 내레이션(더빙)용 소스를 구분한다. 장면은 영상마다 스틸 2~3장(처음·중간·끝)만 확인한다(`ffmpeg -ss 시각 -i 파일 -frames:v 1 -vf scale=640:-1 임시경로.jpg`). 이미지 확인은 토큰을 많이 쓰므로 아래 "이미지 확인 절약"을 따른다.

## 2. 받아 적기와 컷 계획

```
python SKILL_DIR/scripts/transcribe.py "<내레이션/영상 파일>" --out "%TEMP%\words.json"
```

- 단어별 시각이 담긴 JSON이 나온다. 반복·더듬은 문장은 마지막 완전한 테이크를 남기고, 의도적인 반복·강조는 살린다.
- 3초 이상 말이 없는 구간과 군말은 원본 시각 기준으로 시작·끝·이유를 정리한다. 자를 때 숨 여유 약 0.15초, 이음새 20~50ms 크로스페이드를 둔다.
- 영상 컷은 소재에 맞게 실제로 나눠 배치한다. 컷 수·장면·길이는 매번 실제 소재로 정하고, 내용 축약은 요청한 범위에서만 한다.

## 3. 더빙 WAV

원본은 보존하고, 전체 길이의 깨끗한 WAV를 작업 폴더에 만든다(자르지 않는다. 삭제는 `.dsp`의 조각으로 표현한다).

```
ffmpeg -y -i "<내레이션 원본>" -vn -af "highpass=f=80,loudnorm=I=-16:TP=-1:LRA=11" -ar 48000 -c:a pcm_s16le "<작업 폴더>\<원본명>_edited.wav"
```

다 만든 뒤 `ffmpeg -i "<wav>" -af ebur128=peak=true -f null -`로 LUFS·트루피크를 재측정해 -16 LUFS 근처, -1 dBTP 이하인지 확인한다.

## 4. .dsp 만들기

규격은 `references/dsp-v1.txt`. 핵심만:

- `clips`: 영상 소스를 원본 전체 파일로 참조하고 컷 경계는 `in`/`out`으로만 적는다. 더빙이 있으면 `mute: true, vol: 0`. 클립 `fit`은 지정이 없으면 `contain`, `scale` 100, `rot` 0.
- `audio`: 더빙 WAV 하나를 조각마다 `in`/`out`/`start`로 참조한다. 삭제 구간만 건너뛴다. 영상과 더빙을 합치거나 컷마다 음성을 나누지 않는다.
- `media.name`은 폴더 안 실제 파일 이름과 확장자·공백·괄호까지 같게 쓴다.
- `canvas`·`tpl`(`fitMid` 포함)·제목·자막 스타일은 `편집설정.json` 값을 그대로 복사한다. 자막 스타일은 사용자가 저장한 자막 스타일(롱폼·강의·숏폼)이라 크기·위치·색·글자 배경(`box`,`boxColor`,`boxOpacity`)까지 그대로 두고, 가로 영상이라고 줄이거나 옮기지 않는다.
- 가로(16:9)로 만들 때 **세로로 찍은 영상**(probe의 "보이는 크기"가 세로인 파일)은 `편집설정.json`의 `portrait`대로 한다: `rot90`(기본)이면 그 영상 조각의 `rot`를 90, `rot270`이면 270, `fit`은 `contain`(가로 화면에 꽉 찬다). `keep`이면 돌리지 않는다. 자르거나 흐린 배경으로 채우지 않는다. 이미 가로인 영상은 건드리지 않는다.
- 강의·화면 녹화 영상이면 4-1의 화면 강조도 함께 만든다(도형 규격은 `references/dsp-v1.txt` 끝부분).
- `편집설정.json`의 `title`이 null이거나 `canvas`가 `16:9`(가로)면 제목 글자와 색 띠 템플릿은 만들지 않는다(`tpl`은 null, 자막만 하단에). 컷 편집은 항상 한다.
- 자막과 제목: 더빙 조각 목록을 `pieces.json`(`[{"start":0,"in":0,"out":4.2}, ...]`)으로 저장해 만든다.

```
python SKILL_DIR/scripts/make_texts.py --words "%TEMP%\words.json" --pieces "%TEMP%\pieces.json" --settings "<작업 폴더>\편집설정.json" --title "첫줄\n둘째줄" --max-chars 14 --out "%TEMP%\texts.json"
```

  가로(16:9)는 `--max-chars 26`으로 하고 `--title`은 빼며, 자막 스타일은 `편집설정.json`의 `subtitle` 값을 그대로 쓴다(크기·위치를 바꾸거나 줄이지 않는다). `texts.json`의 항목을 `.dsp`의 `texts`에 넣는다. 제목이 필요한 경우에만 영상 내용으로 두 줄을 지어 처음부터 끝까지 표시한다. 문장이 어색하게 끊긴 줄은 직접 고친다.
- 파일은 `<작업 폴더>\결과\<이름>.dsp`로 저장한다.

## 4-1. 강의·화면 녹화 영상: 화면 강조는 기본으로 넣는다

`편집설정.json`의 `lecture`가 `true`이거나, 영상이 강의·실습·사용법·화면 녹화(프로그램·웹·스마트폰 화면을 보며 따라 하는 영상)이면 자막만 넣고 끝내지 않는다. 아래를 `texts`에 함께 넣는다. 사용자가 "자막만", "하단 자막만", "제목·색 띠 빼고"라고 해도 그 말은 **제목 글자와 색 띠를 빼라는 뜻**이다. 화면 강조(도형·확대)를 빼라는 뜻으로 읽지 않는다. 사용자가 "강조 효과 빼 줘", "도형 넣지 마"라고 직접 말했을 때만 넣지 않는다.

- 버튼·메뉴·입력칸을 눌러야 하는 말이 나오는 순간: 그 위치에 `arrow`(화살표) 또는 `rect`/`ellipse`(테두리만, `fill:false`)를 넣고, 실제로 누르는 순간에는 `click`(클릭 표시)을 넣는다. 위치는 해당 시각의 스틸 이미지를 보고 화면 %로 정한다(이미지 확인은 "이미지 확인 절약" 규칙 안에서). 위치를 확신할 수 없으면 넣지 않는다(엉뚱한 곳을 가리키는 것보다 낫다).
- 단계가 끝났거나 결과가 확인되는 순간: 해당 위치에 `check`(체크)를 넣는다. 선택·체크 항목을 설명할 때는 `checkbox`, 하면 안 되는 것·틀린 예를 말할 때는 `cross`.
- 작은 글씨나 좁은 영역을 읽어 줘야 하는 구간: `zoom`(부드러운 확대)을 넣는다. 확대 중심 `x`,`y`는 보여 줄 곳으로 하고, 서로 겹치지 않게 한다.
- 설명에 쓰이는 스크린샷·예시·비교 자료가 따로 있으면 그 말을 하는 타이밍에 띄운다.
- 도형은 한 번에 한 곳씩, 길어야 2~4초. 자막과 핵심 글자를 가리는 위치는 피한다.
- 보고에 어떤 시각에 어떤 강조를 몇 개 넣었는지 적는다. 하나도 넣지 않았다면 그 이유를 적는다.

### 이미지 확인 절약 (토큰 절약)

이미지 한 장은 글자보다 훨씬 많은 토큰을 쓴다. 아래를 지킨다.
- 이미지는 가로 640px 이하로 줄여서 본다(`-vf scale=640:-1`). 여러 장면은 `-vf "fps=1/N,scale=320:-1,tile=3x3"`처럼 한 장에 모아(타일) 한 번에 본다.
- 스틸은 전사(words.json)에서 "누르세요·클릭·선택·열어·입력·확인" 같은 말이 나온 시각에서만 뽑는다. 말이 없는 구간, 설명만 하는 구간은 이미지를 보지 않는다.
- 영상 한 편에서 이미지 확인은 전체 합쳐 20장(타일 기준 약 5~6번)을 넘기지 않는다. 한도를 넘길 것 같으면 넓게 훑지 말고 강조 후보를 가장 확실한 곳 위주로 줄인다.
- 같은 화면이 이어지는 구간은 한 번만 본다. 한 번 본 위치는 다시 확인하지 않는다.
- 더 볼 필요가 없으면 스틸 확인 없이 확대(`zoom`)와 체크(`check`)는 말의 타이밍만으로 넣을 수 있다. 위치가 필요한 화살표·테두리·클릭 표시만 이미지를 본다.
- 보고에 이미지를 몇 장 확인했는지 적는다.

검수에서 강의 영상인데 도형·확대가 하나도 없으면 빠뜨린 것이 아닌지 다시 확인한다.

## 5. 검수 (끝내기 전 필수)

```
python SKILL_DIR/scripts/validate_dsp.py "<작업 폴더>\결과\<이름>.dsp"
```

✗ 오류는 모두 고친다. △ 주의는 의도한 것인지 확인하고 아니면 고친다(영상 합계와 더빙 끝 시각 차이, 더빙이 있는데 영상 소리가 켜진 경우, 설정과 다른 자막 스타일 등). 컷 경계의 클릭음·음량 차·발화 잘림·남은 군말은 편집된 음성을 구간별로 다시 전사하거나 `silencedetect`로 확인한다. 실제로 편집기에서 재생해 보지 못했다면 "구조 검증만 했다"고 구분해서 말한다.

## 6. 보고 (한국어)

만든 파일 위치, 영상 컷 수, 음성 원본/최종 길이, 삭제 구간 수·시간, 최종 LUFS·트루피크, 검수에서 남은 주의를 알린다. 열기 순서는: 단동샘 편집기 → 자동 편집 → 이 작업 폴더의 "결과"에서 `.dsp` 열기. MP4 렌더본은 요청했을 때만 만든다.
